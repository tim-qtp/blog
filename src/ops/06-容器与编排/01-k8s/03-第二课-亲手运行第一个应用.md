# 第二课：亲手在 Kubernetes 中运行第一个应用

## 这节课只做一件事

把 Nginx 放进 Kubernetes，亲眼看到它运行、访问它、查看日志，然后删除它。

这一课不展开集群架构，也不讲 API 分组。先获得完整操作体验，后面再解释每一步为什么有效。

## 一、今天只认识三个新词

### 集群（Cluster）

运行 Kubernetes 的整个环境叫集群。你的实验集群由 Docker Desktop 提供，目前只有一台可用机器，足够完成入门实验。

### Pod

Pod 是 Kubernetes 中运行应用的最小单位。现在先把它理解成“装着容器的运行小盒子”：

```text
Pod
└── Nginx 容器
```

Pod 和容器并不完全相同，具体区别以后单独讲。

### kubectl

`kubectl` 是操作 Kubernetes 的命令行工具。现在只需要这样理解：

```text
你输入命令 → kubectl 把要求交给 Kubernetes
```

## 三、读懂今天要运行的文件

实验文件：`labs/02-第一个应用/01-nginx-pod.yaml`

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: qingyun-mall-web-preview
spec:
  containers:
    - name: nginx
      image: nginx:1.27
      ports:
        - containerPort: 80
```

现在不背字段，只把它读成一句话：

```text
请创建一个名为 qingyun-mall-web-preview 的 Pod，
里面运行一个 nginx:1.27 容器，
Nginx 使用 80 端口。
```

| YAML | 白话意思 |
|---|---|
| `kind: Pod` | 我要创建一个 Pod |
| `name: qingyun-mall-web-preview` | Pod 的名字 |
| `image: nginx:1.27` | 使用 Nginx 1.27 镜像 |
| `containerPort: 80` | Nginx 在容器中使用 80 端口 |

其余字段下一课再拆解。

## 四、创建 Pod

执行：

```bash
kubectl apply -f labs/02-第一个应用/01-nginx-pod.yaml
```

可能看到：

```text
pod/qingyun-mall-web-preview created
```

- `pod/qingyun-mall-web-preview` 是刚创建的对象；
- `created` 表示 Kubernetes 接受了创建请求。

`created` 不等于 Nginx 已经可以访问。接下来要检查它是否真正运行。

## 五、观察 Pod 启动

执行：

```bash
kubectl get pod qingyun-mall-web-preview -w
```

`get pod` 是查看 Pod，`-w` 是持续观察变化。可能依次看到：

```text
NAME              READY   STATUS              RESTARTS   AGE
qingyun-mall-web-preview   0/1     ContainerCreating   0          1s
qingyun-mall-web-preview   1/1     Running             0          4s
```

看到 `Running` 后按 `Control + C` 退出观察。

| 列 | 当前阶段的理解 |
|---|---|
| `READY 1/1` | 1 个容器需要就绪，目前 1 个已就绪 |
| `STATUS Running` | Pod 已运行起来 |
| `RESTARTS 0` | 容器没有被重启 |
| `AGE` | Pod 创建了多久 |

`Running` 仍不能单独证明网页正确，所以还要真正访问它。

## 六、在浏览器中访问 Nginx

执行：

```bash
kubectl port-forward pod/qingyun-mall-web-preview 18080:80
```

看到：

```text
Forwarding from 127.0.0.1:18080 -> 80
```

等待这行出现后再打开浏览器；端口转发刚启动的瞬间，连接可能尚未准备好。

这表示建立了一条临时通道：

```text
你的 Mac 端口 18080 → Pod 中 Nginx 的 80 端口
```

保持终端不要关闭，浏览器访问：

```text
http://127.0.0.1:18080
```

看到 `Welcome to nginx!`，才证明请求确实到达了 Nginx。访问完成后回到终端，按 `Control + C` 停止转发。

`port-forward` 只是临时调试通道，不是正式发布方式。后面会用 Service 解决稳定访问问题。

## 七、查看应用日志

执行：

```bash
kubectl logs qingyun-mall-web-preview
```

刚才访问过网页后，日志中通常能看到类似记录：

```text
"GET / HTTP/1.1" 200
```

`200` 表示这次 HTTP 请求成功。现在你完成了一个最小验证闭环：

```text
看运行状态 → 实际访问网页 → 从日志确认收到请求
```

## 八、查看启动过程

执行：

```bash
kubectl describe pod qingyun-mall-web-preview
```

输出很多，现在不要从头背。只滚到最下面的 `Events`，它表示这个 Pod 的近期事件。通常能看到：

```text
Scheduled → Pulling → Pulled → Created → Started
```

白话意思是：

```text
选择机器 → 拉取镜像 → 创建容器 → 启动容器
```

以后 Pod 起不来，Events 是最先查看的位置之一。

## 九、清理实验

先确认目标：

```bash
kubectl get pod qingyun-mall-web-preview
```

然后删除：

```bash
kubectl delete -f labs/02-第一个应用/01-nginx-pod.yaml
```

最后回读：

```bash
kubectl get pod qingyun-mall-web-preview
```

看到 `NotFound`，表示清理完成。

## 十、完整过程

```text
读取 YAML
   ↓
kubectl apply 创建 Pod
   ↓
Pod 中启动 Nginx
   ↓
port-forward 建立临时通道
   ↓
浏览器访问成功
   ↓
logs 确认请求
   ↓
delete 清理 Pod
```

## 十一、问题与直接回答

### 为什么创建后还要执行 `kubectl get pod`？

因为 `created` 只说明 Kubernetes 接受了请求，不代表容器已经成功运行。

### 为什么还要打开浏览器访问？

因为 `Running` 不等于业务内容正确。真实请求成功才是更进一步的证据。

### `18080:80` 两边分别是什么？

左边 `18080` 是你的 Mac 端口，右边 `80` 是 Nginx 在 Pod 中使用的端口。

### `port-forward` 是正式发布方式吗？

不是。它适合学习和临时调试，命令停止后通道就消失。

### Pod 启动卡住，先看什么？

先用 `kubectl get pod` 看状态，再用 `kubectl describe pod Pod名称` 查看底部 Events。

## 本课只记住四件事

1. Pod 是 Kubernetes 运行应用的最小单位。
2. `kubectl apply -f` 根据 YAML 创建对象。
3. 创建成功、Pod Running、网页可访问是三个不同层次。
4. 初步验证顺序是状态 → Events → 实际请求 → 日志。
