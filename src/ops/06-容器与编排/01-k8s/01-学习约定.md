# 学习约定：快速吸收模式

## 1. 课堂节奏

每个知识单元只引入一个核心概念，并按下面顺序讲解：

1. **白话引入**：它解决什么具体问题？
2. **动手看到结果**：命令逐条执行，每一步解释输入和预期输出。
3. **解释原理**：只解释刚才已经观察到的现象。
4. **常见问题**：问题和答案直接给出。
5. **压缩记忆**：最后只保留 3～5 个结论。

默认不安排问答验收、考试、自评分或等待过关。快速吸收指减少低价值内容，不代表跳过基础、堆叠术语。

## 2. 三本账

学习期间始终维护三类记录：

- **对象账**：我创建了什么，它的 owner、selector、状态分别是什么？
- **流量账**：请求从哪里来，逐跳经过什么，在哪一跳失败？
- **变更账**：我改了什么，观察到什么，如何回退？

需要留证时统一记到 `学习记录/`，不要只在终端滚屏里留下证据。

## 3. 命令纪律

- 每次先确认 context：`kubectl config current-context`。
- 所有课程资源进入独立 Namespace，避免误伤别的环境。
- 删除前先确认对象类型、名称和 Namespace。
- `apply` 后必须 `get/describe` 回读，不能把 “configured” 当作成功上线。
- 遇到故障先收集状态、Events、日志，再修改或重建。
- 不使用 `latest` 镜像标签作为正式实验版本。
- 清理命令单独列出，不与创建命令绑在一条长命令中。

## 4. 内容压缩原则

每一课优先保留：

- 一句核心结论；
- 一张对象关系或请求链路图；
- 一个最小正确示例；
- 一个最常见故障；
- 一组“问题 + 直接回答”。

低频字段和可随时查阅的参数不占课堂篇幅。需要时使用 `kubectl explain` 和官方文档查询。

## 5. 我们如何配合

后续按概念依赖关系循序推进，并直接提供问题与答案。一个术语没有用白话解释和实际观察过，就不拿它解释下一个术语。你可以在下面三种情况打断我：

1. 某个概念没有听懂；
2. 实际输出与课件不同；
3. 希望对某个生产场景深入展开。

否则课程直接向前推进，不安排等待回答的验收环节。
