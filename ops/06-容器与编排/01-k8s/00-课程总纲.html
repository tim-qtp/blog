                                                              # Kubernetes 系统课总纲

                                                              # 一、结课时你要具备什么能力

                                                              结课不是「视频看完」或「命令抄完」，而是能独立完成下面五件事：

                                                              1. 讲清楚：用自己的话解释 Pod、Deployment、Service、Ingress、PVC 等对象为什么存在。
                                                              2. 部署好：把前端、后端、配置和数据层部署进集群，并完成升级与回滚。
                                                              3. 看得见：能从对象状态、Events、日志、指标和网络路径收集证据。
                                                              4. 查得准：面对 Pending、CrashLoopBackOff、ImagePullBackOff、服务不通等问题，沿链路定位而不是碰运气。
                                                              5. 守得住：理解资源边界、健康检查、权限、备份、高可用和变更风险。

                                                              这门课不承诺把所有 Kubernetes API 都讲完。它要建立一张可靠的地图，让你以后遇到陌生对象也知道该从哪里查。

                                                              # 二、两条贯穿全课的主线

                                                              # 主线 A：控制链（期望如何变成现实）

                                                              YAML / kubectl
      ↓
kube-apiserver → etcd 保存状态
      ↓
控制器发现差距 → 创建/更新对象
      ↓
scheduler 为未调度 Pod 选择 Node
      ↓
kubelet 驱动容器运行时 → 容器真正运行

                                                              以后看到「为什么没创建」「为什么没调度」「为什么没启动」，先判断卡在这条链的哪一段。

                                                              # 主线 B：请求链（流量如何找到不断变化的 Pod）

                                                              集群外客户端
   ↓
Ingress / Gateway / LoadBalancer
   ↓
Service（稳定入口）
   ↓
EndpointSlice（当前健康后端清单）
   ↓
Pod IP : containerPort

                                                              以后看到「浏览器不通」「域名能解析但 502」「Service 没后端」，沿这条链逐跳验证。

                                                              # 三、课程阶段

                                                              默认采用循序渐进的快速吸收模式：每课只引入一个核心概念，先实操看到结果，再解释术语和原理。减少低价值记忆，但不跳过基础。

                                                              阶段建议周数核心内容阶段作品 / 过关标准
                                                              0. 建立地图0.5K8s 解决什么、集群组件、API 对象、kubectl 观察法能读懂控制链，分清期望状态和实际状态
                                                              1. 工作负载1Pod、标签、Deployment、ReplicaSet、滚动更新、回滚、Job/CronJob发布并回滚一个无状态 Web 服务
                                                              2. 配置与访问1Namespace、ConfigMap、Secret、Service、DNS、Ingress配置外置；前后端通过稳定服务名通信
                                                              3. 数据与可靠性1Volume、PV/PVC、StorageClass、StatefulSet、探针、requests/limitsPod 重建后数据仍在；错误实例不接流量
                                                              4. 调度与安全1调度约束、污点容忍、驱逐、ServiceAccount、RBAC、SecurityContext解释 Pending；给账号最小权限
                                                              5. 可观测与排障1Events、日志、exec/debug、指标、审计思路、故障树完成一组未知故障的证据化定位
                                                              6. 交付与运维1Kustomize、Helm、镜像策略、升级回滚、备份、高可用与容量认知用 Helm/Kustomize 管理多环境发布
                                                              结业项目1+完整应用上线与演练部署、升级、故障注入、恢复、复盘全部留证

                                                              # 四、详细课表

                                                              # 阶段 0：建立地图

                                                              1. Kubernetes 到底在解决什么：从 docker run 到持续纠偏
                                                              2. 第一次完整实操：创建、观察、访问、看日志、清理 Pod
                                                              3. 从实操反推 YAML：apiVersion、kind、metadata、spec
                                                              4. 集群组件与 kubectl 的基础证据链

                                                              # 阶段 1：工作负载

                                                              1. Pod 生命周期：从 Pending 到 Running
                                                              2. 多容器 Pod：共享网络/存储与 Sidecar 边界
                                                              3. 标签与选择器：Kubernetes 对象的“连接器”
                                                              4. Deployment 与 ReplicaSet：副本、自愈和所有者关系
                                                              5. 发布工程：滚动更新、暂停、回滚与版本证据
                                                              6. Job / CronJob：一次性与周期性任务

                                                              # 阶段 2：配置与访问

                                                              1. Namespace：隔离边界与它不能解决的问题
                                                              2. ConfigMap / Secret：配置与镜像解耦
                                                              3. Service：为什么 Pod 有 IP 还需要稳定入口
                                                              4. DNS 与服务发现：名字如何变成地址
                                                              5. Ingress：HTTP 流量如何进入集群
                                                              6. 网络排障：从客户端逐跳验证到 Pod

                                                              # 阶段 3：数据与可靠性

                                                              1. 容器文件系统与 Volume：哪些数据会消失
                                                              2. PV / PVC / StorageClass：存储供需模型
                                                              3. StatefulSet：稳定身份、顺序和存储
                                                              4. 存活、就绪、启动探针：三种“健康”不能混用
                                                              5. requests / limits：调度承诺和运行边界
                                                              6. 优雅终止与可用性：从 SIGTERM 到流量摘除

                                                              # 阶段 4：调度与安全

                                                              1. scheduler 如何做决定，Pending 如何读
                                                              2. nodeSelector、亲和性、污点与容忍
                                                              3. ServiceAccount 与 RBAC：谁可以对什么做什么
                                                              4. SecurityContext 与 Pod Security Standards
                                                              5. NetworkPolicy 与镜像/Secret 安全边界

                                                              # 阶段 5：可观测与排障

                                                              1. Events、日志与状态：证据的时间顺序
                                                              2. exec、port-forward、临时调试容器
                                                              3. CPU、内存、OOM、驱逐与资源故障
                                                              4. 网络/DNS 故障树
                                                              5. 控制面与节点异常的判断边界
                                                              6. 综合故障挑战：只给现象，不给答案

                                                              # 阶段 6：交付与运维

                                                              1. Kustomize：原生 YAML 的环境差异
                                                              2. Helm：Chart、values、升级和回滚
                                                              3. 生产变更：版本固定、发布验证与回退点
                                                              4. 集群安装与生命周期：Docker Desktop、kind、kubeadm、托管 K8s 的边界
                                                              5. 高可用、备份恢复、升级与容量规划认知
                                                              6. 监控、日志、告警与 SLO 入门

                                                              # 结业项目

                                                              1. 部署一个含 Web、API、数据库的应用，完成：
                                                              • 配置与 Secret 外置
                                                              • Service / Ingress 访问
                                                              • 持久化与备份说明
                                                              • 健康检查和资源限制
                                                              • 滚动升级与回滚
                                                              • RBAC 最小权限
                                                              • 至少 5 个故障注入及证据化复盘

                                                              # 五、暂时不深挖的内容

                                                              Operator/CRD 开发、Istio/eBPF 深度原理、超大规模调度优化、多集群管理，不适合放在零基础主线里。主课结束后再按工作需要选修。

                                                              CKA 也不是本课程的第一目标。先获得真实理解和排障能力，再做考试题型训练会更稳。

                                                              # 六、版本与资料原则

                                                              • 实验以本机集群的实际 API 为准，不死背网络文章里的旧参数。
                                                              • 课堂命令先在本机验证，再写入讲义。
                                                              • 重要术语回到 Kubernetes 官方文档核对。
                                                              • Kubernetes 小版本持续演进；具体支持周期、默认行为和废弃 API 在使用前重新确认。
