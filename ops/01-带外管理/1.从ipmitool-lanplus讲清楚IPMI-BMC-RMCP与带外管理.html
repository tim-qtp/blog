                        # 从 ipmitool -I lanplus 讲清楚 IPMI、BMC、RMCP+ 与带外管理

                        在服务器运维中，经常会看到这样的命令：

                        ipmitool -I lanplus -H 192.168.1.100 -U admin -P password power status

                        对于刚接触服务器带外管理的人来说，这条命令里往往会有几个疑问：

                        • lanplus 到底是什么意思？
                        • IPMI 2.0、RMCP+ 又是什么？
                        • ipmitool 是装在被管理服务器上的吗？
                        • 为什么连接的是 BMC，而不是服务器本身？
                        • BMC IP 和服务器操作系统 IP 有什么区别？

                        本文从最基础的概念开始，把这条链路完整讲清楚。

                        # 1. 先用一句话理解整个过程

                        可以先记住：

                        ipmitool 是“发命令的人”，BMC 是“服务器内部负责接收带外管理命令的小电脑”，lanplus 是两者通过网络通信时使用的一种接口模式。

                        完整链路可以理解为：

                        ipmitool
   ↓
-I lanplus
   ↓
IPMI 2.0
   ↓
RMCP+
   ↓
UDP/IP 网络
   ↓
BMC
   ↓
服务器硬件

                        # 2. lanplus 是什么？

                        lanplus 并不是一个严格意义上的英文缩写，而是 ipmitool 对一种网络接口模式的命名。

                        可以简单理解为：

                        LAN + Plus

                        也就是：

                        比传统 lan 模式更完整、更安全的 LAN 网络通信方式。

                        在 ipmitool 中，常见的远程接口主要有：

                        -I lan
-I lanplus

                        可以做一个简单对比：

                        接口常见对应通信方式特点
                        lanIPMI 1.5RMCP较老
                        lanplusIPMI 2.0RMCP+支持更完整的认证、完整性校验和加密能力

                        因此，在现代服务器远程带外管理中，通常更常见的是：

                        -I lanplus

                        # 3. IPMI 是什么？

                        IPMI 全称：

                        Intelligent Platform Management Interface

                        中文通常翻译为：

                        智能平台管理接口

                        它是一套服务器硬件管理规范。

                        IPMI 关注的不是 Linux、Windows 中的业务应用，而是服务器本身的硬件状态和控制能力，例如：

                        • 电源状态
                        • 开机
                        • 关机
                        • 重启
                        • CPU 温度
                        • 主板温度
                        • 风扇转速
                        • 电源模块状态
                        • 电压
                        • 硬件传感器
                        • 系统事件日志

                        例如：

                        ipmitool power status

                        用于查询服务器电源状态。

                        ipmitool power on

                        用于开机。

                        ipmitool power off

                        用于关机。

                        # 4. RMCP 是什么？

                        RMCP 全称：

                        Remote Management Control Protocol

                        可以理解为：

                        远程管理控制协议

                        它是一种比较轻量的网络管理协议，用于让管理端通过网络和服务器的管理控制器通信。

                        传统 IPMI 1.5 的网络通信可以简单理解为：

                        IPMI
 ↓
RMCP
 ↓
UDP
 ↓
IP 网络

                        IPMI 远程管理常见使用：

                        UDP 623

                        一个非常简单的通信过程可能是：

                        运维服务器
    │
    │ RMCP / IPMI
    ↓
   BMC
    │
    ├── 查询温度
    ├── 查询风扇
    ├── 查询电源
    └── 控制开关机

                        # 5. RMCP+ 又是什么？

                        RMCP+ 可以理解为 RMCP 的增强版本。

                        其中的 + 就是 “Plus” 的意思。

                        通常可以这样记：

                        IPMI 1.5  → RMCP

IPMI 2.0  → RMCP+

                        相比早期 RMCP，RMCP+ 增加了更完善的安全机制，包括：

                        • 身份认证
                        • 会话管理
                        • 数据完整性校验
                        • 加密保护
                        • 密钥协商

                        因此，当我们执行：

                        ipmitool -I lanplus \
  -H 192.168.1.100 \
  -U admin \
  -P password \
  power status

                        它并不是简单地把用户名、密码和命令直接裸发给 BMC。

                        实际过程可以粗略理解为：

                        ① 找到 BMC
   ↓
② 建立 RMCP+ 会话
   ↓
③ 双方进行身份认证
   ↓
④ 协商会话参数
   ↓
⑤ 建立受保护的 Session
   ↓
⑥ 发送 IPMI 命令
   ↓
⑦ BMC 返回执行结果

                        # 6. RAKP 是什么？

                        在 IPMI 2.0 的 RMCP+ 会话建立过程中，还会涉及一个重要机制：

                        RAKP

                        全称：

                        Remote Authenticated Key-Exchange Protocol

                        简单理解就是：

                        用于客户端和 BMC 之间完成身份认证和会话密钥协商的一套机制。

                        对于普通运维人员来说，不需要一开始就深入密码学细节。

                        只需要先建立下面这个认识：

                        RMCP+
=
网络通信
+
身份认证
+
Session 会话管理
+
完整性保护
+
可选加密

                        这也是为什么 lanplus 一般比传统 lan 更适合现代远程服务器管理。

                        # 7. BMC 到底是什么？

                        BMC 全称：

                        Baseboard Management Controller

                        中文通常称为：

                        基板管理控制器

                        它可以理解为：

                        服务器内部独立存在的一台“小电脑”。

                        一台服务器实际上可以粗略理解为拥有两套相对独立的系统：

                        ┌─────────────────────────────┐
│         物理服务器           │
│                             │
│  ┌───────────────────────┐  │
│  │ Linux / Windows       │  │
│  │                       │  │
│  │ 运行业务程序           │  │
│  │ Nginx / Java / DB     │  │
│  └───────────────────────┘  │
│                             │
│  ┌───────────────────────┐  │
│  │ BMC                   │  │
│  │                       │  │
│  │ 独立管理控制器         │  │
│  │ 管理服务器硬件         │  │
│  └───────────────────────┘  │
│                             │
└─────────────────────────────┘

                        BMC 通常拥有自己的：

                        • 处理器
                        • 内存
                        • 固件
                        • 网络接口
                        • IP 地址
                        • 用户体系

                        因此，即使服务器上的 Linux 已经死机，BMC 仍然可能正常工作。

                        # 8. 服务器操作系统 IP 和 BMC IP 是两回事

                        这是理解带外管理最重要的一点。

                        假设有一台服务器。

                        操作系统的业务 IP 是：

                        10.0.0.20

                        BMC 的管理 IP 是：

                        192.168.1.100

                        这两个 IP 可以完全不同。

                        例如：

                        业务网络

Linux
10.0.0.20
   │
   └── Web / Java / MySQL / Kubernetes

                        而另外一边：

                        带外管理网络

BMC
192.168.1.100
   │
   └── IPMI / Redfish / 远程电源控制

                        所以：

                        -H 192.168.1.100

                        通常指定的是：

                        BMC 的 IP 地址

                        而不是 Linux 或 Windows 的 IP。

                        # 9. ipmitool 到底装在哪里？

                        答案是：

                        不一定安装在被管理服务器上。

                        在实际远程带外管理场景中，通常会安装在一台统一的运维服务器或管理节点上。

                        例如：

                        运维服务器
192.168.1.10

                        安装：

                        ipmitool

                        然后管理多台服务器：

                                                 ┌── BMC-01
                         │   192.168.1.101
                         │
运维服务器 + ipmitool ───┼── BMC-02
                         │   192.168.1.102
                         │
                         └── BMC-03
                             192.168.1.103

                        也就是说：

                        不需要在几十台被管理服务器上分别安装 ipmitool。

                        只需要管理端能够访问这些 BMC IP 即可。

                        # 10. 一条 ipmitool -I lanplus 命令到底发生了什么？

                        例如：

                        ipmitool -I lanplus \
  -H 192.168.1.100 \
  -U admin \
  -P password \
  power status

                        可以拆成：

                        参数含义
                        ipmitoolIPMI 命令行客户端
                        -I指定 Interface，也就是通信接口
                        lanplus使用 IPMI 2.0 / RMCP+ 网络模式
                        -HBMC 的 Host/IP
                        -UBMC 用户名
                        -PBMC 密码
                        power status查询物理服务器电源状态

                        整个通信链路是：

                        运维服务器
192.168.1.10

    │
    │ ipmitool
    │
    │ IPMI 2.0
    │ RMCP+
    │ UDP/IP
    ↓

BMC
192.168.1.100

    │
    │ 查询主板电源状态
    ↓

服务器硬件

                        # 11. 为什么不直接 SSH 到服务器？

                        因为 SSH 和 IPMI 管理的层级不同。

                        SSH 管的是：

                        操作系统

                        IPMI / BMC 管的是：

                        物理服务器硬件

                        比如 Linux 已经死机：

                        Linux
  ↓
SSH ×

                        这时候可能已经无法登录：

                        ssh root@10.0.0.20

                        但是 BMC 可能仍然正常：

                        BMC
192.168.1.100
   ↓
正常

                        于是仍然可以通过：

                        ipmitool -I lanplus \
  -H 192.168.1.100 \
  -U admin \
  -P password \
  power reset

                        直接对物理服务器执行重启。

                        所以可以这样记：

                        SSH
=
管理操作系统

                        而：

                        IPMI / BMC
=
管理服务器硬件

                        # 12. 什么叫“带外管理”？

                        “带外管理”英文通常叫：

                        Out-of-Band Management

                        它的核心思想是：

                        使用一条独立于服务器业务系统的管理通道来管理服务器。

                        正常业务链路可能是：

                        用户
 ↓
业务网
 ↓
Linux
 ↓
应用程序

                        带外管理链路则是：

                        运维人员
 ↓
管理网
 ↓
BMC
 ↓
服务器硬件

                        即使：

                        Linux 崩溃
业务网络异常
应用程序挂掉

                        只要：

                        BMC 正常
管理网络正常

                        运维人员通常仍然可以执行：

                        • 查询硬件状态
                        • 开机
                        • 关机
                        • 强制重启
                        • 查看传感器
                        • 查看系统事件日志

                        这就是带外管理最大的价值。

                        # 13. -I open 和 -I lanplus 有什么区别？

                        如果 ipmitool 就安装在被管理服务器自己的 Linux 系统里，还可以通过本机 IPMI 驱动访问 BMC。

                        例如：

                        ipmitool -I open sensor

                        可以理解为：

                        Linux
 │
 │ 本机 IPMI 内核驱动
 ↓
BMC

                        这种方式属于：

                        本地访问 BMC

                        而：

                        ipmitool -I lanplus ...

                        则是：

                        远程运维服务器
 │
 │ 网络
 │ IPMI 2.0 / RMCP+
 ↓
BMC

                        这种方式属于：

                        远程网络访问 BMC

                        简单对比：

                        模式使用场景
                        -I open本机通过 IPMI 驱动访问本机 BMC
                        -I lanplus通过网络远程访问另一台服务器的 BMC

                        # 14. 放到真实运维平台里是什么架构？

                        如果要开发一个“物理服务器带外纳管平台”，一种比较典型的架构是：

                        ┌────────────────────────┐
│        Web 前端         │
│                        │
│ 服务器列表 / 电源控制   │
└───────────┬────────────┘
            │
            ↓
┌────────────────────────┐
│       后端服务          │
│                        │
│ Go / Java 等            │
└───────────┬────────────┘
            │
            ↓
┌────────────────────────┐
│      IPMI 管理层        │
│                        │
│ ipmitool / IPMI SDK     │
└───────────┬────────────┘
            │
            │ IPMI 2.0 / RMCP+
            │
      ┌─────┼─────┐
      ↓     ↓     ↓
    BMC01 BMC02 BMC03
      │     │     │
      ↓     ↓     ↓
   服务器1 服务器2 服务器3

                        后端平台可以统一管理：

                        • BMC IP
                        • 用户名
                        • 凭据
                        • 服务器资产信息
                        • 电源状态
                        • 温度
                        • 风扇
                        • 电源模块
                        • 传感器
                        • SEL 事件日志

                        然后再在 Web 页面中统一展示。

                        # 15. IPMI 和 Redfish 的关系

                        现在的服务器带外管理中，经常还会看到：

                        Redfish

                        可以先简单理解：

                        IPMI
= 比较传统的服务器硬件管理标准

                        而：

                        Redfish
= 更现代、REST API 化的服务器管理标准

                        例如 IPMI 可能使用：

                        ipmitool
RMCP+
UDP 623

                        Redfish 则通常使用：

                        HTTPS
REST API
JSON

                        因此现代带外管理平台经常会采用：

                        优先 Redfish
    ↓
不支持时
    ↓
兼容 IPMI

                        这样可以兼顾新旧服务器。

                        # 16. 最后总结

                        理解 ipmitool -I lanplus，最关键的是建立下面几个概念。

                        # 第一：ipmitool

                        它是一个 IPMI 客户端工具，用来发送服务器硬件管理命令。

                        # 第二：lanplus

                        它是 ipmitool 的一种网络接口模式，通常对应：

                        IPMI 2.0 + RMCP+

                        # 第三：BMC

                        BMC 是服务器内部独立的管理控制器，相当于服务器里的“小电脑”。

                        # 第四：BMC IP ≠ 服务器 OS IP

                        例如：

                        Linux IP：
10.0.0.20

BMC IP：
192.168.1.100

                        它们属于两套不同的管理体系。

                        # 第五：SSH 和 IPMI 管理的不是一层

                        SSH
→ 管操作系统

                        IPMI / BMC
→ 管服务器硬件

                        # 第六：为什么带外管理重要？

                        因为即使：

                        Linux 已经死机

                        只要：

                        BMC 还正常

                        运维人员仍然有机会远程执行：

                        开机
关机
重启
查看硬件状态
查看温度
查看风扇
查看硬件告警

                        因此可以把整个知识体系最后浓缩成一条链路：

                        运维平台
   ↓
ipmitool
   ↓
lanplus
   ↓
IPMI 2.0
   ↓
RMCP+
   ↓
BMC
   ↓
物理服务器硬件

                        理解了这条链路，IPMI、BMC、RMCP+、带外管理以及后续的 Redfish 就基本串起来了。
